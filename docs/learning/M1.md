# M1: Ingestion and storage

## What was built

`insight ingest` takes PPTX and PDF files through render, extract, embed, and store. Slides
become PNGs on disk. Text blocks, tables, chart series, and notes become chunks with vectors
in Postgres. Documents are keyed by content hash, so re-ingesting is a no-op.

## Decisions and why

- **Slide is the retrieval unit, chunk is the search unit.** One vector per block keeps a chart
  from being diluted by the rest of its slide, and `slide_id` collapses results back to slides.
- **Title prefix on embedded text only.** Stored text stays raw so citations show real content.
  It's a setting, so eval can measure whether it helps.
- **PDF table text stored once.** Duplicates would crowd results and inflate storage numbers.
- **sentence-transformers on PyTorch.** Heavier now, but M5 and M6 need PyTorch anyway.
- **One transaction for slides, chunks, and `ready`.** A crash can't leave a half-written document
  marked as finished.

## What surprised us

- LibreOffice leaves hidden slides out of its PDF. Without handling that, every slide after a
  hidden one would have been matched to the wrong image, and gold labels would have been wrong.
- pdfplumber reports a single bordered box as a table, so text in a callout could have been lost
  from the page text.
- Your Mac already runs a Postgres on 5432, so the project's database uses 5433.
- A killed process would have blocked a file from ever being ingested, until we added a staleness
  rule.

2. The title prefix changes what gets embedded but not what gets stored. What might go wrong if
