# M2: Query path and web demo

## What was built

A question is embedded, matched against chunks, and collapsed to its best slides. Those slides'
images and text go to a local vision model, which answers with `[S1]` tags that code maps back to
real slides. An async API serves this, and a static GitHub Pages page replays recorded answers.

## Decisions and why

- **Inline citation tags, checked by code.** Any tag that isn't in the context is dropped, so the
  model can't cite a slide it wasn't shown.
- **Abstaining is a real answer.** "Not found in the documents" clears citations.
- **Recorded demo, not a live app.** A live one needs a paid server and open uploads without auth.
- **`qwen3-vl:4b` and top-k 3 are provisional.** You chose to get the URL up first, so the model
  comparison is deferred. M4 can measure these properly.

## What surprised us

- The sample deck's slides needed about 5,700 tokens, above Ollama's default context of 4,096.
  Without `num_ctx`, the prompt would be cut off.
- Ollama 0.12.9 couldn't pull `qwen3-vl`, despite the minimum listed on its library page.
- The question comparing Q3 with Q4 abstained. The model behaved correctly: the guidance slide
  wasn't retrieved. That is a retrieval miss, which is what later milestones measure.
- macOS can mark `.pth` files in `.venv` as hidden, and Python then ignores them, so `insight`
  stops importing. `chflags nohidden .venv/lib/python3.11/site-packages/*.pth` fixes it.
