# M0: Repo reset and hygiene

## What was built

No product features. The old `app/` code is gone, replaced by `uv` with a lockfile, `ruff`,
`pytest`, a small `insight` CLI, settings read from the environment, CI on every push and
PR, and a README that claims only what exists.

## Decisions and why

- **Delete rather than fix the prototype.** Its bugs were structural: wrong function
  signatures, colliding IDs, and a compose file that can't start. Git history keeps it.
- **One real CLI command instead of empty ones.** An empty `insight ingest` would be a claim
  the code can't back up. Commands and Makefile targets now arrive with their milestones.
- **Static replay for the web demo.** A public live app needs a paid server running a vision
  model and open uploads. A replay is free and always on, but it can't answer new questions.
- **Employer name left out of the committed spec,** since the repository is public.

## What surprised us

- The prototype's compose file could never have worked: no pgvector, no database password,
  and a Dockerfile compose couldn't find.
- Ollama reports the installed Qwen vision models as having no `tools` capability. That
  matters for M7.

## Questions for you

1. Why does committing `uv.lock` matter for a project whose headline output is a results
   table? What could go wrong with the table without it?
2. `/query` ran retrieval twice and reloaded the embedding model each time. Which of those
   would you expect to cost more, and how would you measure it?
3. The old code used a dot-product embedding model with cosine distance. Under what condition
   do those two give the same ranking, and why might this model not meet it?
